# Server Bootstrap

**Автоматизированное развёртывание 3x-ui, Nginx и UFW на Ubuntu и Debian.**

**Данный проект я больше разрабатывал под себя и свои нужды. Какие-либо ошибки буду фиксить по возможности. Описание сгенерировал через ChatGPT, сам код писал сам, кроме некоторых моментов (Python).**

## О проекте

Server Bootstrap — Bash-скрипт для автоматизации развёртывания прокси-серверов.

Основные компоненты:

- **3x-ui** — управление прокси-подключениями.
- **Nginx** — обратный прокси и обработка TLS.
- **UFW** — межсетевой экран и контроль сетевого доступа.

Проект поддерживает локальную установку и удалённое развёртывание через SSH.

## Возможности

- Автоматическая установка и настройка 3x-ui, Nginx и UFW.
- Локальное и удалённое развёртывание.
- Выбор источника установочного скрипта 3x-ui.
- Поддержка существующих TLS-сертификатов и Let's Encrypt.
- Автоматическая проверка на Wildcard сертификат.
- Передача сертификатов на удалённый сервер через SCP.
- Проверка соответствия DNS A-записи публичному IPv4 сервера.
- Настройка Nginx и обратного прокси.
- Настройка правил UFW и ограничение SSH-доступа.
- Автоматическое создание прокси-подключений.

## Установка

Клонируйте репозиторий и перейдите в его директорию:

```bash
git clone https://github.com/OhSenpai1337/server-bootstrap.git
cd server-bootstrap
```

Перед запуском настройте `config.conf` в соответствии со своими требованиями.

Запустите установщик:

```bash
sudo bash setup.sh
```

### Поддерживаемые протоколы

При включённом `XUI_CREATE_INBOUNDS` создаются следующие подключения:

| Протокол | Транспорт | Защита |
|---|---|---|
| VLESS | WebSocket | TLS |
| Hysteria2 | UDP | TLS |
| TUIC v5 | UDP | TLS |

## Режимы установки

### Local

Установка непосредственно на сервере.

Используется локальная конфигурация и выбранный способ получения TLS-сертификата. При запуске из SSH учитывается IP-адрес клиента для настройки правил доступа.

### Remote

Удалённое развёртывание на целевом сервере через SSH.

Управляющая машина передаёт установочные файлы и, при необходимости, wildcard TLS-сертификат. Установка выполняется непосредственно на целевом сервере, после завершения временные файлы удаляются.

Поддерживается подключение как к root, так и к обычному пользователю с правами sudo (не проверено).

## TLS-сертификаты

Поддерживаются два способа использования TLS-сертификатов:

- **Existing** — использование существующих сертификатов.
- **Let's Encrypt** — автоматический выпуск сертификата через Certbot.

При наличии настроенного wildcard-сертификата установщик проверяет, покрывает ли он указанный домен. Если соответствие найдено, сертификат используется автоматически.

При удалённом развёртывании wildcard-сертификат передаётся на целевой сервер. Это позволяет использовать общий сертификат для нескольких серверов без необходимости выпускать отдельный сертификат для каждой ноды.

## Конфигурация

Перед запуском необходимо настроить `config.conf`. При первом запуске, если файл отсутствует, он автоматически создаётся из `config.conf.example`.

## Параметры конфигурации

### SYSTEM

| Параметр | По умолчанию | Описание |
|---|---|---|
| `UPDATE_SYSTEM` | `false` | Обновлять системные пакеты перед установкой. |

### SSH & ACCESS CONTROL

| Параметр | По умолчанию | Описание |
|---|---|---|
| `SSH_EXTRA_IPS` | `[]` | Дополнительные IP-адреса, которым разрешено подключаться по SSH. |
| `SSH_ALL` | `false` | Разрешить SSH-подключения с любых IP-адресов. |
| `USE_SSH_KEYS` | `true` | Включить установку SSH-публичных ключей. |
| `SSH_KEY_ONLY` | `false` | Отключить аутентификацию по паролю и разрешить вход только по SSH-ключам. Требуется хотя бы один ключ в `SSH_KEYS`. |
| `SSH_KEYS` | `[]` | SSH-публичные ключи для добавления в `/root/.ssh/authorized_keys`. |

### SSL / TLS

| Параметр | По умолчанию | Описание |
|---|---|---|
| `SSL_USE_EXISTING` | `true` | Использовать существующие SSL-сертификаты вместо запроса новых через Certbot. |
| `SSL_FULLCHAIN` | `/path/to/fullchain.pem` | Путь к файлу цепочки SSL-сертификатов (`fullchain.pem`). |
| `SSL_PRIVKEY` | `/path/to/privkey.pem` | Путь к приватному ключу SSL-сертификата. Должен соответствовать указанному сертификату. |

**Примечания:**
- Установщик автоматически проверяет наличие существующих сертификатов Let's Encrypt.
- Указанные в конфигурации пути к сертификатам автоматически используются в режиме Local.
- Wildcard-сертификаты, указанные в конфигурации, определяются автоматически.

### 3X-UI

| Параметр | По умолчанию | Описание |
|---|---|---|
| `XUI_INSTALL_URL` | `mhsanaei/3x-ui` | URL установочного скрипта 3x-ui или совместимого форка. |
| `XUI_PANEL_PORT` | `8080` | Порт веб-панели 3x-ui. |
| `XUI_WEB_BASE_PATH` | `/PATH_TO_YOUR_PANEL/` | URL-путь веб-панели. Рекомендуется изменить стандартное значение в целях безопасности. |
| `XUI_VLESS_WS_PATH` | `/VLESS_WS_PATH/` | URL-путь для VLESS WebSocket-подключений. |
| `XUI_SUBSCRIPTION` | `true` | Включить сервис подписок 3x-ui. |
| `XUI_ROSCOMVPN_ROUTING_RULES` | `true` | Включить правила маршрутизации RoscomVPN. |
| `NGINX_SUBSCRIPTION` | `true` | Настроить Nginx в качестве обратного прокси для сервиса подписок. |
| `XUI_SUBSCRIPTION_PORT` | `465` | Порт сервиса подписок. |
| `XUI_SUB_PATH` | `/SUB_PATH/` | URL-путь стандартной подписки. |
| `XUI_SUB_CLASH_PATH` | `/SUB_CLASH_PATH/` | URL-путь подписки Clash. |
| `XUI_CREATE_INBOUNDS` | `true` | Автоматически создавать подключения VLESS-WS, Hysteria2 и TUICv5. |
| `XUI_AUTODETECT_COUNTRY` | `true` | Автоматически определять страну расположения сервера и использовать её в названиях подключений. При отключении используются стандартные названия. |

**Проверенные установочные скрипты:**

- **STANDARD:** [mhsanaei/3x-ui](https://github.com/mhsanaei/3x-ui)
- **PURE:** [vermiliondevil-web/pure-3x-ui](https://github.com/vermiliondevil-web/pure-3x-ui)

## Системные требования

- Ubuntu или Debian.
- Права root для локальной установки.
- SSH-доступ к целевому серверу для удалённой установки.
- Домен с корректной DNS A-записью.
- Для удалённой установки — доступность SSH и возможность передачи файлов через SCP.

Необходимые системные пакеты и дополнительные зависимости устанавливаются автоматически.

## Безопасность

Установщик выполняет базовую настройку безопасности сервера, включая настройку UFW и ограничение SSH-доступа согласно конфигурации. Дальнейшая настройка, обслуживание и обеспечение безопасности сервера остаются на ответственности пользователя.
